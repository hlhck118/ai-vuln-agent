# 外部暴露面测绘

## 什么时候该用它

你手上是 IP、CIDR 或域名，并且想知道：哪些地址活着、开了哪些端口、端口后面是什么服务、
有没有未授权访问。这条路全部由**内置探测**完成，不需要外部工具，也不需要大模型——
结论来自可复现的协议交互。

## 下发

```
start_probe target=10.0.0.5 ports=common objective="内网办公段暴露面测绘"
start_probe target=10.0.0.0/24 ports=1-1024
start_probe target=app.example.com
start_probe target=10.0.0.5:80,443,8080
```

`target` 可写单 IP、CIDR、域名，也可写 `host:ports` 形态。`ports` 省略时用内置常见端口
集合；`common` 取人工整理的常见服务端口表（不是流量统计排序）；`all` 等于 1-65535。
全端口单主机约需数十秒；多主机全端口会超出连接预算被拒。

规模上限写在 `scope.py` 里，是**展开阶段**就拒的硬约束，不是运行到一半才发现：

- 单次最多 256 个地址（`MAX_HOSTS`，/24 正好 254 个可用地址）；
- 端口数上限就是整个 TCP 空间 65535 个（`MAX_PORTS`）；
- 真正的那道护栏是**连接预算** `MAX_PROBES = 262144` = 地址数 × 端口数。全端口单主机是
  65535 次连接，预算允许四台一起扫；`/24` × 全端口 = 1660 万次，会在展开阶段被拒。

越界目标会让 `create_job` 抛错，错误原样回到你手里。那不是故障，是部署者设的门禁——
告诉用户目标越界、以及需要把哪个网段加入 `--probe-scope`，**不要换个写法重试**。

## 产出什么

一次探测产出四类东西，全部落在**本对话对应的 engagement** 下：

- **资产**：每个存活地址、每个开放端口与其服务名；
- **事实**：banner、延迟、TLS 版本与证书指纹、HTTP 状态行；
- **可判定弱点**（直接生成 finding，不需要人工再判）：Redis 未授权（`PING` 回 PONG）、
  Docker API 未授权（2375/2376 可无凭据调用，定级 critical）、Elasticsearch 未授权
  （9200 根接口无凭据可达）、TLS 证书未通过校验、TLS 接受已废弃版本（1.0/1.1）。
- **图**：`get_chain_overview` 给标题，`get_chain_nodes` 给正文。

**端口开放本身不计入 finding**——这是刻意的，否则一份清单会被"开放了 22 端口"淹没，
而真正要看的是后面那几条。同理，未授权判定必须真的发出协议请求并读到应答，不是靠端口号猜。

## 服务识别怎么做，边界在哪

连通性扫描之后只对**开放**端口做识别：HTTPS 端口走 TLS 握手 + HTTP 指纹，HTTP 端口走
明文 HTTP，6379 走 Redis `PING`，2375 走 Docker `/version`，9200 走 ES 根接口。未知端口
先试 HTTP 再试 TLS——顺序有讲究：明文 HTTP 服务收到字节会回状态行，TLS 服务收到明文 GET
通常直接断连，两种误判都不会发生。跳过这一步的代价是"跑在 8080 之外的 web 服务一个都认
不出来"，而那恰恰是最常见的情况。

连不上、超时、或者目标在总时长上限（900 秒）之前没扫完，会在结果的 `degraded` 里写明
"未完成的部分未计入结论"。**看到 `degraded` 就要转述**，不要把它当成完整结论的一部分。

## 长输出怎么读全

探测结果的正文很长（每台主机每个端口的 banner 与证书细节都在里面）。读的时候：

```
get_chain_overview engagementId=E-xxxx          # 只有标题，先看规模
get_chain_nodes kind=fact limit=40              # 正文，按节点分页
get_chain_nodes nodeId=fact-70                  # 只要那一条
get_assets limit=100                            # 资产，按条分页
get_job jobId=job-xxxxxxxx                      # 任务原始结果
```

这四个读取口都返回同一套信封：`total` / `count` / `limit` / `offset` / `nextOffset` /
`hasMore`。**只看第一页会把"还没读到"当成"只有这些"**——报告的规模常常是这个默认页的
好几倍。要读全就一路带 `nextOffset` 翻到 `hasMore` 为 false，然后把"共 N 条、我读了 M 条"
写清楚；没读全就说明没读全，不要用第一页的条数当结论。

## 代价与边界

- 探测只建立连接、读一段应答、断开，不改变目标状态；但它是**真实的网络动作**，会进目标
  的访问日志。
- 全端口扫描是 65535 次连接，在网络设备上会留下明显痕迹，也会占用执行节点的连接表。
  不是必须就把范围收窄。
- 指纹识别依赖端口号对服务的映射，SERVICE_NAMES 只用于展示与链路事实，**判定逻辑不依赖它**。
  一个跑在 8888 上的 SSH 会被标成 http-alt，这时要看 banner，不要信应用名。
- 域名会被解析成地址；解析结果是会变的。所以域名与 CIDR 在授权判定里比不了——域名要放行
  就在白名单里写域名。
