# 内网横向

## 什么时候该用它

你手上有一台"能借网络位置给我们"的机器：一次载荷投递落地成功后登记的立足点，或一台已知的
SSH 跳板。你要回答的问题是——**经它，我能看到它背后什么**。注意这句话里的宾语：这不是
"它是什么"，也不是"我拿到它了"，而是"**经它可达什么**"。

## 第一步：先看立足点登记表

```
list_footholds
list_footholds includeClosed=true
```

登记表里每条给出：哪台机器、凭什么给出口（`kind`：socks5 / tunnel / webshell / ssh /
agent）、`capability`、背后标注了哪些网段（`scope`）、什么时候登记的、是哪次任务登记的
（`jobId`）。**这是已观测事实，不是计划**——在此之后目标可能已经不可达，所以用它之前仍要
过一次出口验证。

立足点登记是**自动**的：`deliver_payload` 落地确认成功时会登记一条。手工录入的立足点（比如
一台已知的跳板）不需要先走一次落地确认，直接用 `open_pivot` 指定 `target` 即可。

## 第二步：开出口并验证

```
open_pivot target=10.0.0.5 egress=["10.0.0.9:445","10.0.0.0/24"] footholdKind=socks5
open_pivot target=10.0.0.5 egress=["10.0.0.9:445"] tunnel=true hop=1
```

几条硬规则：

- **`egress` 必填。** 没有出口目标的任务证明不了任何事，只会白担一次开通道的风险。
- **`target` 若与某个已登记立足点同主机，会自动沿用那条登记**——`kind`、`capability`、
  背后网段都会跟着用上。查不到才按参数现拼。
- `egress` 里的每一项可以是 `host`、`host:port`、URL，或一个网段。网段会先按额度判规模、
  超了**拒绝**（不是截断）；网段没写端口时按默认端口验证，并在 `degraded` 里标明"这个端口
  是假设"——**这一条必须转述**，否则读的人会把一次假设当成观测。
- `tunnel=true` 走端口转发，**只接受一个出口目标**：隧道就是"一个本机端口 → 一个固定目标"，
  多列几个而只验其中一个，汇总里的计数会骗人。要验证多个目标用 SOCKS5。
- `hop` 是"已经跳了几跳"。跳数上限是为了让"这条结论是从哪里观测到的"始终有个答案。

## 出口是**用完就关**的，留下的东西是证据

任务起一个出口、**经它真的连一次**每一个出口目标、验证可达性，然后**关掉出口**。结果里的
`endpoint` 是"本次观测用了哪个出口"的记录，**不是一条可以拿来用的入口**，`exitClosed: true`
说的就是这件事。

为什么不留着：任务结束后还留着的出口，没法回答"这条结论是从哪里观测到的"。而这个平台的
全部价值就建立在那句话上——每一条结论都要能指着一次具体的观测。

出口的每个目标会落成 `open` / `closed` / `filtered` / `denied` / `unknown` 之一。
**`denied` 与 `unknown` 都要与 `closed` 分开报**：被规则拒绝、连观测手段都没有，与
"端口关着"是三件不同的事，处置也完全不同。

## `open_pivot` 不生成交付项（finding）

这是刻意的：这一步的产物是**可达性**，不是漏洞。把"经跳板能连上一个端口"写成交付项，会让
报告里出现一批没有影响说明的高危。链路里落的是：

- 立足点 → **资产**（`meta` 里写清种类、能力、被标注的背后网段）；
- 经它可达的目标 → **资产**，挂在立足点下面；
- 不可达、被拒、未判定的目标 → **事实**——它们同样是观测结果，而且往往比"开着什么"更有用
  （"这个网段里没有 Web"是一条能立刻收窄范围的结论）。

## 与"它是什么"的区别

一次出口验证能给的：经它，`10.0.0.9:445` 可达、这个网段里哪些地址有响应。
它**不能**给的：那台机器是什么操作系统、445 后面是不是 SMB、服务版本。那些要另外下发
`start_probe` 或 `run_tool adapter=nmap`，而且要注意：**经出口的探测**与**直连的探测**在
这个平台上目前是两件事——`open_pivot` 自己只验证可达性，不接力做后续扫描。所以汇报时要说清
"这是经立足点观测到的可达性"，不要把可达性当成服务指纹。

## 代价与边界

- 这一类动作会在这台机器上放一个不受本机策略约束的通道——授权的意思是承认这一点。
  配额：最多跳 2 跳、出口存活上限 30 分钟、单次最多 64 个出口目标。
- **立足点自己必须过闸**，而且与**每一个**出口目标各自过闸：只判出口目标等于允许任何一次
  被授权的验证顺带在一台从未被授权碰的机器上开通道。整条一起判——有一个目标不在白名单里
  就整条不跑，而不是"跳过那一个"（那会让一次越权的任务看起来像一次部分成功的任务）。
- 本部署 `authz.FORCE_OPEN=True`：pivot 类的准入判定不参与判定，**不要**让用户去配
  `--allow-intrusive`；仍然生效的是探测作用域与权限档。
- SSH/SMB 这些协议的**认证**能力不在本模块里：`pivot` 用的是已建立的立足点，不是口令。
  要测口令另见凭据测试那一份手册，那里写了 SSH/SMB/RDP 在常见部署上为什么是断的。
- 输出与结果用 `get_job` 按字符分页读；`get_chain_nodes kind=asset` 读立足点与出口资产的正文。
