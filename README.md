# AI 智能体渗透测试工作台

> 版本 v2（内部版本号 `2.0.0`）。把「探索链路」能力（目标 → 意图 → 事实 → 漏洞 → 资产）
> 从宿主插件里独立提取出来，配以控制面服务、Web 界面与可分离的执行节点，
> 构成一套**不依赖任何宿主应用**的渗透测试工作台。

扫描与验证由内置的 AI 智能体漏洞发掘引擎完成，网络探测由内置的确定性探测引擎完成——
结论全部来自可复现的协议交互，不经过模型推断。

## 特点

- **零第三方依赖**：只用 Python 标准库 + 原生 JS/SVG，无构建步骤，内网离线可跑
- **一个 Python 进程 + 浏览器**就是全部部署形态，不需要 Docker
- **C/S 可分离**：控制面进程内自带一个本机执行节点；够不到的网段再接远程节点
- **工具装进项目目录**：外部客户端落在 `data/tools/`，不改 PATH、不写注册表，删目录即还原

## 快速开始

```bash
cd ai-vuln-agent
python deploy/start.py          # 自动选端口并打开浏览器
# 或
python -m pentestd serve --port 8787
```

仓库根还有更短的路径，两个壳是同一条路：Linux / macOS / Git Bash 用 `./start.sh`，Windows 用 `start.bat`。它们只做一件事——找到 Python 3.10+，把参数原样交给 `deploy/start.py`（`start.sh` 用 `exec`，Ctrl+C 直接打到控制面）。`./start.sh --host 0.0.0.0` 让同一内网能打开，`./start.sh --port 9000` 换端口。

Windows 上还多三个把「远程访问」拼好的短写法：`start.bat --lan`（等于 `--host 0.0.0.0`）、`start.bat --remote`（绑 `0.0.0.0` 并另开一个窗口起 `tools/keep_tunnel.py`）、`start.bat --tunnel`（只起隧道）。其余参数照样原样转发。

启动后在浏览器里完成：创建管理员账号（**没有默认口令**）→ 选推理模型 → 部署自检 → 下发任务。

## 目录结构

```text
pentestd/     控制面服务、任务调度、AI 引擎、工具适配器
web/          前端（无构建步骤，原生 ES 模块）
deploy/       启动器与部署脚本
tools/        运维与打包脚本
tests/        测试套件（unittest，零依赖）
data/         运行期状态（不进版本库；data/skills/ 例外，是产品内容）
prototype/    AI 漏洞发掘引擎
vendor/       随项目分发的 DSH 运行时（node_modules 不进版本库）
```
